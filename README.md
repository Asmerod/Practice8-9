# Прогнозирование финансового временного ряда EUR/USD

**Практические работы № 8–9 по дисциплине «Анализ данных и машинное обучение» (АДиМО)**  
Магистратура · Команда № 2 · Валютная пара **EUR/USD**

## О проекте

Проект посвящён сравнительному исследованию методов прогнозирования дневной цены закрытия валютной пары EUR/USD на **1 и 5 торговых дней вперёд**. Исследование выполнено на исторических котировках за согласованный годовой период и объединяет подготовку данных, анализ временного ряда, построение прогнозных моделей, независимое тестирование, исследование устойчивости и документирование результатов.

**Цель** — установить, способны ли более сложные статистические, ансамблевые и нейросетевые методы улучшить прогноз относительно простого наивного подхода (**Persistence**), а также определить, как качество зависит от горизонта и выбранной метрики. Превосходство сложной модели не предполагается заранее.

## Исходные данные

- **Объект исследования:** валютная пара EUR/USD.
- **Источник котировок:** [Dukascopy — EUR/USD](https://www.dukascopy-node.app/instrument/eurusd).
- **Частота:** дневные торговые свечи (D1).
- **Основные поля:** дата и котировки OHLC (*Open, High, Low, Close*).
- **Исследуемый период:** согласованный командой приблизительно 12-месячный интервал 2025–2026 годов. Точные даты фактических наблюдений, характеристики временной зоны, сторона котировки и выполненные преобразования приводятся в **паспорте данных**.
- **Прогнозируемая величина:** будущая цена закрытия `Close` после 1 либо 5 торговых сессий.

Исходные материалы проверялись на корректность временного индекса, порядок дат, пропуски, дубликаты, типы значений, аномальные движения и согласованность OHLC. Подробные решения по качеству и подготовке данных документированы отдельно; README не заменяет паспорт данных.

## Методология исследования

### Временное разделение и защита от утечек

Временной ряд разделён **хронологически** на три периода: `Train` для обучения, `Validation` для настройки и выбора конфигураций, `Test` для итоговой независимой оценки. После фиксации конфигураций модели повторно обучались на `Train + Validation` и проверялись на `Test`.

Прогноз для момента \(t\) использует только информацию, доступную после завершения торговой сессии \(t\). Применены проверки корректности целевых дат, формирования признаков и окон последовательностей. Масштабирование обучалось только по соответствующему обучающему периоду. Во время последовательного прогнозирования ARIMA допускается обновление состояния по уже завершённым сессиям без переоценки параметров.

### Сравниваемые методы

| Семейство | Метод | Основная идея |
|---|---|---|
| Наивное прогнозирование | **Persistence** | Будущий Close принимается равным последнему известному Close |
| Классическое статистическое | **ARIMA** | Моделирование временной структуры логарифма цены |
| Ансамблевое машинное обучение | **Gradient Boosting** | Прогноз будущей логарифмической доходности по набору исторических и рыночных признаков |
| Рекуррентные нейросети | **GRU** | Прогноз доходности по последовательности торговых наблюдений |

Для горизонтов **1 и 5 дней** использовались отдельные конфигурации. Выбор моделей проводился по **RMSE на Validation**; при финальном тестировании гиперпараметры больше не изменялись.

### Метрики и дополнительные проверки

- **MAE, RMSE, sMAPE** — точность прогноза цены; MAE и RMSE также представлены в пунктах EUR/USD (*pips*).
- **Directional Accuracy** — доля верно предсказанных направлений изменения; **Directional Coverage** — доля прогнозов с ненулевым направлением.
- **Сравнение с Persistence** — относительное улучшение или ухудшение ошибки.
- **Временная устойчивость** — оценка качества на двух последовательных частях тестового периода.
- **Статистическая неопределённость** — парный круговой блочный бутстрэп ошибок относительно Persistence.
- **Вычислительные затраты** — время обучения и прогнозирования в использованной программной среде.

Дополнительно исследованы простые стратегии прогнозирования направления («всегда повышение», «всегда снижение», большинство в обучении, повторение последнего движения), чтобы не приписывать моделям преимущество, которое может объясняться распределением направлений рынка.

## Основные результаты

Все четыре семейства оценены на одинаковых датах внутри каждого горизонта: **39 тестовых прогнозов** для 1 торгового дня и **35** — для 5 торговых дней.

| Горизонт | Метод | MAE, pips ↓ | RMSE, pips ↓ | Directional Accuracy, % ↑ |
|---|---|---:|---:|---:|
| 1 день | Gradient Boosting | 22,494 | **31,591** | **53,85** |
| 1 день | Persistence | **21,667** | 31,624 | 0,00 |
| 1 день | GRU | 22,074 | 31,635 | 46,15 |
| 1 день | ARIMA | 21,877 | 31,757 | 48,72 |
| 5 дней | GRU | **67,236** | **81,096** | 54,29 |
| 5 дней | ARIMA | 70,186 | 82,612 | 51,43 |
| 5 дней | Persistence | 70,377 | 83,063 | 0,00 |
| 5 дней | Gradient Boosting | 71,173 | 84,612 | **65,71** |

**Интерпретация результатов:**

- На горизонте **1 день** минимальную RMSE получил Gradient Boosting, однако выигрыш относительно Persistence составил лишь около **0,10%**. По MAE лучшим оказался Persistence: явного универсального лидера нет.
- На горизонте **5 дней** GRU показала минимальные MAE и RMSE (улучшение RMSE относительно Persistence — около **2,37%**). Gradient Boosting лучше определял направление, однако его преимущество относительно простой стратегии «всегда снижение» составило только **один верный прогноз из 35**.
- Лидеры по RMSE **менялись между Validation и Test**, а также между первой и второй половинами Test. В частности, преимущество пятидневной GRU не сохранялось на обеих половинах тестового периода.
- По представленным результатам блочного бутстрэпа **95%-е интервалы улучшения MAE относительно Persistence включали ноль**. Это не даёт оснований утверждать устойчивое превосходство по данной метрике.

**Вывод:** качество зависит от прогнозного горизонта, метрики и исследуемого рыночного периода. Усложнение модели само по себе не гарантирует улучшения относительно наивного прогноза.

Это **резервный вариант**, а не требование при обычном запуске.

Если на Google Drive есть **несколько копий** проекта с одноимёнными датасетами, код остановится с перечислением найденных вариантов, чтобы не выбрать случайный файл. При очень большом объёме личного Google Drive такой поиск может занять дополнительное время; указание точного каталога также ускоряет запуск.

### Дополнительные замечания по воспроизведению

- **Финальный Test не используется для повторного подбора моделей.** Ноутбук выполняет зафиксированный протокол обучения, тестирования и проверки устойчивости; повторный запуск нейросети может дать немного отличающиеся значения.
- Для формирования **подробного паспорта** экспортные ячейки читают **сохранённую копию `.ipynb`** из папки `notebooks/`. Перед запуском последних блоков сохраните ноутбук с результатами выполнения; настройка Colab, запрещающая сохранять выводы ячеек, должна быть выключена.
- Повторная сборка отчётов и изображений использует папку `results/`. Уже опубликованные паспорта и графики **доступны для просмотра без запуска кода**.
- Проверку только итоговых выводов удобнее начинать с [`results/Паспорт исследования (Краткий АО).md`](results/Паспорт исследования (Краткий АО).md), а изучение полного протокола — с [`results/Паспорт исследования (Подробный АО).md`](results/Паспорт исследования (Подробный АО).md) вместе с каталогом PNG.

- Годовая история EUR/USD и небольшой финальный Test ограничивают надёжность обобщений.
